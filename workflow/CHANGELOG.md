## v6.6 — 2026-09-23

**影响文件**:`SKILL.md` / `references/execution-standard.md` / `references/workspace.md` / `assets/templates/exec-card.md` / `VERSION` / `CHANGELOG.md`

⚠️ **`execution-standard.md` 本版有改动 —— 执行端须重新同步挂载副本**(§四-4.3)。

**性质**:改一条既有判据的对象(校验权威从容器改到内容)+ 系统文件枚举扩容。按总则3.1③ 取**次版本位**——旧的 zip 值判据仍保留为辅助,不构成破坏性变更。

**触发 · 实证**:v6.5 present 之后,用户手上出现一份 **91663 bytes / MD5 `0ff7f885da76934f429e9c78933ac6bc`** 的 zip,而签发件是 **83728 / `9ccd640a…`**;两份包内 `SKILL.md`(`6604ab0a…`)与 `execution-standard.md`(`df577128…`)的 MD5 **完全一致**,差额 7935 字节是多出来的 `__MACOSX/` 目录。
起因是 macOS 把下载的 zip 自动展开、再由 Finder 重新压缩,把扩展属性写成 `__MACOSX/._*` 打了进去。**内容一字未改,信封换了。**

**根因**:v6.1 定下「present 包必带字节数与 MD5」时,**把权威钉在了压缩容器上**。容器值受下游系统行为影响,而那正是签发方控制不到的部分。
本轮 EXEC-WF-001 落地时手拿到的是签发件、判定命中、结果有效;但只要用户再下载一次、系统再压一次,**下一张卡就会把一个完全正确的包判成「不命中」而整卡停下——白跑一轮,且错的是判据不是包。**

### 1. `SKILL.md` §2 总则3.1 新增「包内容指纹」,并降级 zip 值为辅助

指纹算法写死在该节(排除系统文件 → `LC_ALL=C` 排序 → 每行 `{相对路径}  {MD5}` → 整份清单取 MD5),附一条可照抄的命令,mac / Linux 通用。
**中间清单 `wf-manifest.txt` 本身是诊断件**:指纹不符时直接 diff 两份清单就知道差在哪个文件,不必逐个猜。

### 2. `execution-standard.md` §八 新增「核一个包对不对」三步

zip 值不命中 **不等于包错、不要就此停下** → 解压后核内容指纹:
- 指纹命中 → 判「**同内容、不同容器**」,**可用**,反馈里标一行并报出实际用的文件全名与其 zip 值;
- 指纹不命中 → 才是真不对,停下报回,**并附上算出的清单**;
- 卡里只给 zip 值、没给指纹 → 标 ⚠️ 要指纹,不自行推算、不拿别的文件顶替。

同节「解压」条目:`__MACOSX/` / `.DS_Store` / `._*` 改为**只报计数,不删、不报为偏差**。

### 3. `workspace.md` §二 系统文件枚举扩到 `__MACOSX/` 与 `._*`

v6.2 立这条时只写了 `.DS_Store`——**又是一次按旧事实集写死的枚举**,`__MACOSX/` 和 `._*` 本就是同一类东西,只是到 v6.6 才在实战里撞上。这已经是同族坑的第三次(总则6 漏扩主线-手 / 单窗口假设 ×2 / 本条),**枚举句是这套规则最稳定的故障点**。

### 4. `exec-card.md` §一 出卡前记住的事从三件加到四件

卡里要用到某个包时,权威值给内容指纹,zip 值只作辅助供下游认人。
