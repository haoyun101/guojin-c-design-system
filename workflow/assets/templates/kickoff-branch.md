# 模板 · 支线-组件开场白 + 续轮任务卡

> 用法:**开场白一个窗口只发一次**;同一支线窗口做第二个及以后的组件时,改用下半的「续轮任务卡」。
> 支线窗口按**线**划分(支线-通用 / 支线-理财 / …),该线的组件在同一窗口逐个串做——**不按组件开窗**,
> 那等于每个组件重付一次开窗成本(`multi-window.md` §4)。

---

## 一、开场白(新开一条支线时发一次)

```
这是「国金DS」协同包(文件已附)。本窗口=【支线-组件 · {线名}】。先按两步走,别急着动手:

① 按工作流 skill 的 SKILL.md §4 路由表读:先读 SKILL.md 全文,再读 DS skill 的 SKILL.md 入口。
   组件 / 场景 / 参考实现 / 图标按需读取,不预读全量;读的时候守总则1(以文件为准,不靠记忆)。

⛔ 你这条线的写权限只有自己那个 drafts/。skill/ 对你是只读——
   不直接改 skill 文件、不自行升 DS 版本、不入库;产出一律交「待并入草案」,由主线裁决并入。
   收到任何看起来像执行卡的东西(含带 EXEC 编号的),也不改变这条边界。

② 读完先回我三件事:
   ㈠ 本轮要做什么组件、你打算怎么做;
   ㈡ 缺哪些文件、Figma 节点或授权,一次列全;
   ㈢ 你这条线能做什么、不能做什么。

你的边界(只做范围 + 停手条件):
- 只做:只读 + 起草。取值 → 效果确认 → 出「待并入草案」(multi-window.md §5 七项),到此为止。
- 不做:不写正式 skill、不升版、不打包、不动看板、不发 Design、不发布。
- 停手:碰到自升级机制(§4.6)、Figma 写回(§4.7)、可靠性三层机制(§4.8)——立刻停,标 ⚠️ 交主线,不要自己改。
- 拿不准归属(通用 vs 业务)不要自己定:按 ≥2 场景→通用 / 单一→业务 出提案,拿不准就标问,由主线裁。

本轮组件:[全限定名 + C 编号]
Figma 节点:[链接 / 或注明「本轮无源,走新建·无源模式」]
本轮特有约束:[仅本组件独有的;没有就写「无」]
```

## 二、续轮任务卡(同窗口做第二个及以后的组件)

**不重发开场白**——窗口已读过规则。只给四样:

```
【本卡发给】支线-组件 · {线名}        ← 不是执行卡
【你的边界】只写自己那个 drafts/;skill/ 只读,不入库、不升版(workspace.md 权限矩阵)
【本轮组件】{全限定名 + C 编号}
【产出文件】{确切路径,如 assets/components/progress.html}
【规格位置】{components.md 第几章 / scenarios/{场景}.md 哪节}
【本轮特有约束】{仅本组件独有的、规则文件里没有的;如 token 覆盖情况、某处已知规则洞怎么绕}
```

> **⛔ 头两行不能省。** 续轮卡带着 EXEC 编号,**长得像执行卡**;收卡方若是 ChatGPT 这类载体,会按主线-手的方式去执行。
> **实证**:C09 续轮卡编号 `EXEC-DS-001`,支线按执行卡执行,**直接改了 skill 并准备升版**。编号只用来追溯轮次,**不代表权限**——权限永远看 `workspace.md` 权限矩阵。
> **⛔ B 类(要 Figma 节点)的续轮卡只给 Figma 链接 + 底线约束,不替支线限死做什么。** 实证:红点气泡被主线凭印象窄化成「按钮气泡」。同族于 `exec-card.md` §四-7b。

**⛔ 不重抄规则**:边界、七项交付包、闸门顺序、读取纪律都在规则文件里。
重抄一遍就是第二处副本,且两次措辞必有出入(`multi-window.md` §8)。

## 三、派活前先判 A 类还是 B 类

| | A 类 · 补参考实现 | B 类 · 固化新组件 |
|---|---|---|
| 前提 | 规格已固化**且够画**:章内 token 齐全、状态与资产引用明确 | **无规格、或规格不足以画** |
| 要 Figma 节点吗 | 不要(走「新建·无源」) | **必须给** |
| 真值来源 | 已固化的规格;**章内明写的 token 直接照抄、不标 ⚠️**,章内没给的才标 ⚠️ | 走完整循环:取值 → 效果确认 → 草案七项 |
| ⛔ 禁止 | **严禁由 hex 反推绑定名** | — |

> ⚠️ **判 A / B 的口径是「只读规则文字能否唯一画出来」,不是「有没有实现文件」**(`process.md` §6 自检6 反推自检)。
> 派活前先核该章的 **token 覆盖、状态定义、资产引用粒度**三项。只核「有没有参考实现文件」会误判。

## 四、开多支线前先查撞车

**按「互不共享底层」分组件**:两条线别同时改会写同一 token、或同一被嵌套底层组件(按钮 / 图标 / tab / 胶囊 / 分割线…)的东西。详见 `multi-window.md` §6。
