# 模板 · 执行卡

> **先问一句:这一轮真的要动本地工作区吗?** 只换包、不动 `meta/` 以外任何东西的,**把包放进 Project 文件就算到位,不必出卡**(`SKILL.md` §2 总则3.1)。要归档旧目录、要同步执行端挂载副本、要整理 `历史文件/` —— 这些才需要卡。
>
> 用法:主线-大脑写给【主线-手】的指令。**长任务**(超过 5 条、或含逐字替换)落成 md 文件;
> **短任务**(3 条以内)直接贴回复——**但两者共用同一条 EXEC 编号序列**,不存在「短任务免编号」。

---

## 一、文件名与编号

**编号与文件名规则正文在 `SKILL.md` §3.2**,此处不重抄。出卡前只需记住三件:

1. 编号是 `EXEC-{窗口码}-{三位序号}`,**窗口码查《项目总览》§三**,序号接本域上一张。
2. 文件名 `{编号}-{任务摘要}.md`,**摘要必须含对象**(✅ `land-v6-5` ❌ `land-package`)。
3. 出完把本域最大号回写《项目总览》§三 登记表。
4. **卡里要用到某个包时,权威值给「包内容指纹」**,zip 字节数 + MD5 只作辅助、供下游在下载夹里认人。算法与理由在 `SKILL.md` §2 总则3.1,此处不重抄。

## 二、怎么送到手上

1. 大脑 present 执行卡 md → 用户下载到 `~/Downloads`
2. 用户把下面的**转交复制框**整段粘给手
3. 手执行 → 写反馈 md 到 `~/Downloads` → 回复只给路径
4. 用户把该反馈 md 拖给大脑

### ⛔ 执行卡必须和转交复制框同轮一起给(总则6)

**只 present 执行卡 md 不算交付完**——用户还得自己组织一段话转交,那是把大脑的活推给用户。
**每次出执行卡,同一轮必须附下面这个框**,用户直接粘、不用改。

**框里就这三行,不加别的:**

```
$guojin-design-system-executor

执行 ~/Downloads/{编号}-{摘要}.md
```

> **⛔ 框内不写摘要、要点、备注、注意事项。** 卡是自包含的,收件方一打开就看得到;框里再写一遍就是第二处副本,而且两处必然对不上(`process.md` §7.1)。
> **判据**:这行字卡里有没有?**有 → 不进框。**
> **连「本轮有几个文件」都不进框**——卡的任务1 本来就要写明本轮用哪几个输入,收件方一打开就看得到。

**框外**(给用户看,不进框)只写一件:
- **发之前先确认 `~/Downloads` 里有哪几个文件**——逐个点名,少一个对应任务会停下。
  **这是给用户的下载清单,收件方不需要**;写在框外,框内那份就不必有。

> **⛔ 卡点名的活动件,在落地前一并冻结。** 卡里写了某活动件的确切校验值,那份文件在反馈回来之前不要再改;期间改动攒着,落地后一次写入。
> **⛔ 卡一经 present 即视为定稿。** 要改就换卡号重发,并明说「旧卡作废」——
> 原地用编辑工具改,用户下载的仍是旧版,手照旧版执行,下一轮还得补一张卡修文案。

## 三、卡的骨架

```
# {编号} · {任务摘要}          ← 例:EXEC-DS-007 · 归档旧目录

- 签发:主线-大脑
- 日期:{YYYY-MM-DD}
- 涉及版本:{如 WF v6.9 / DS v4.1.1;没有就写「无」。**真值查《项目总览》§二**,不照本行举例抄}

## 前置声明

- 本卡是否含不可逆操作:{是/否}
- 若含,主线-大脑裁决:{确认删除 / 确认移动 / 确认覆盖},确切目标见各任务
- 授权范围:{列出本卡会碰到的目录}

## 任务1:{标题}

- 目标:{一句话,做成什么样算完成}
- 操作:{逐条,动词明确:建/移/复制/改名/解压/打包/跑脚本}
- 验证:按常规
        ⛔ 默认就写「按常规」四个字。§六 已经写死移动 / 复制 / 改名 / 新建 / 解压 / 打包 / 跑脚本
           各自怎么验,重抄一遍是第二处副本——实测抄出来的副本是原件的 3.3 倍长。
        只有两种情况才写内容,且要写明「超出常规」:
        ① 本轮要核的东西 §六 没有(如权威 MD5、字节数、VERSION 内容)
        ② 本轮有特殊留证需求(如「确认 C02 / C09 未被误改」)

## 任务2:...

## 完成后回报

按 execution-standard.md §五 的反馈模板输出 md 到 ~/Downloads,文件名带本卡编号。
```

## 四、写卡的八条纪律

> **总纲:卡里只写「常驻规范里查不到的、且只有大脑能定的」那部分。** 其余八条都是这句话的展开。

1. **给动作,不给理解性指令。** ❌「把某处改清楚些」 ✅「查找这段原文 → 替换为这段」(逐字给全)。
2. **不可逆操作必须预授权。** 删除 / 覆盖 / 移动类任务在卡里写明「主线-大脑裁决:确认删除」+ 列确切目标,否则手会停下来问,白费一轮。
3. **锚点以工作区现有文件为准,不照 Project 快照推断。** 快照会把点号转成下划线(`_v1.3` → `_v1_3`),照快照写锚点会整项失配。
4. **别越界指望手。** 手对工作区外路径(下载文件夹只读、挂载目录)的权限有限,涉及那些位置先查 `execution-standard.md` §四。
5. **文本改动给脚本,不给「查找→替换」。** 凡改已有文件的文字内容(插条目、换措辞、改版本号),一律给一段可照抄运行的 Python;脚本内 `assert` 锚点唯一,失败即停、不试别的锚点。
   **理由**:「查找→替换」把执行方式的选择留给了下游——补丁工具遇长行易失配,而**失败的补丁本身就是大块无效 token**;整份读入再写回则把文件塞进模型上下文。脚本方式文件内容只进 Python 进程、**不进模型上下文**,锚点不符时当场失败、不产生半份补丁。
   **锚点取最短唯一片段**——越长越容易有一个字符对不上(EXEC-036 任务 10.5 即因 400 字长锚点里一处粗体星号差异而整项落空)。
   例外:新建文件、二进制操作、目录级动作(建 / 移 / 改名 / 打包)不适用。
6. **验证项合并成一条命令。** 同一任务的多项验证(字节数 / 锚点命中数 / 清单)写成一条命令打印几个数字,不逐项各发一次——分散列会诱导下游反复重扫。

7. **不重抄常驻规范,也不替手做它自己能做的判断。** 两半:

   **a · 不重抄规范。** 验证方式、反馈格式、路径约定、异常处置都在 `execution-standard.md`,卡里只写本轮特有的。
   判法就是 `process.md` §7.1 的**删除测试**,把对象换成「执行卡 ↔ 常驻规范」——删掉后手照常驻规范还能做对,就删。

   **b · 给目标,不给路线。** 卡写**做什么 / 做到什么样算完成**,不写**怎么找、用什么命令、按什么顺序 stat**。路径写到**能唯一定位的最小粒度**即可(通常到目录级 + 文件名特征),剩下交给执行端——它有本地访问、有 §四 路径约定,自己定位比大脑隔空猜准。
   **⚠️ 边界:这只针对定位与工具选择,不针对动作本身。** 做什么仍要逐字给全(纪律1 不变);不给的是「去哪个目录找、用什么命令找」。
   **仍须写死的四种**:① 不可逆操作的确切目标(纪律2 要求);② 顺序不可调时的顺序;③ 同名文件有歧义时的辨别依据;④ 本轮特有的约束。
   **实证**:EXEC-035 把 `button.html` 的位置写死成 `~/Downloads`,实际草案在 `drafts/common/C01-button_2026-09-22/`,整卡作废重发。**大脑写错路径的代价是一整轮,手自己找的代价是几条命令。**

   > **拿不准时默认把定位条件写松,让手报回实际使用的路径**,不为此单跑一轮只读卡。
   > **例外**:下一步是不可逆操作且目标可能不唯一时,仍先出只读卡——纪律2 要求卡里列出确切目标,列不出就不能授权。

8. **非紧急小改动攒批,不单独发卡。** 单项改动 < 3 行、且不阻塞任何下游动作的,记入待办,并进下一张实质卡。
   **判据**:这条不改,下一步会不会做错或做不了?**会 → 立刻发;不会 → 攒着。**
   **攒的条目记入《项目总览》§四 待办并标 ⏸攒批**,不由出卡方自行记忆——靠记忆维持跨轮状态,这个项目已经付过账。
   **理由**:每轮的固定成本(手读常驻规范 + 读卡 + 写反馈)是 20 KB 量级,远大于一两行改动本身。EXEC-030~037 八轮里至少三轮属于这种。

## 五、短任务贴回复的格式

```
【{本轮编号} · 本轮任务】
1. {动作}
2. {动作}
```

编号照样给。反馈形态**不因任务短而降级**——仍按 `execution-standard.md` §五 落盘 md。
