# 模板 · Design 复制框

> 用法:主线-大脑同步定稿内容给【支线-站点(Design)】时用。规则出处:`process.md` §5.4。
> **第一原则:主交付物是参考实现文件本身,不是这个框。** 能给文件就别让它重画——
> 参考实现是像素级正确的唯一真源,Design 吃 prose 重画 = 每个表述缝放大成一整轮。
> 这个框退为「差异说明 + 归属 + 版本」,配着文件一起发。

---

## 一、有参考实现文件时(首选)

先把文件给用户转交,复制框里写:

```
【DS v{X.Y.Z}】{组件全限定名} —— 按附件 1:1 渲染

附件:{文件名.html}
位置:{实际页面名}.html → 「{章节区块名}」,作为该页新增区块加入(非新开页面)

渲染要求:
1:1 照此渲染 —— 只针对「组件本体」:尺寸、token、状态、资产。
图标 / 资产一律用文件内的,禁自画、禁内联近似、禁自行简化。
颜色一律走 var(--token),不要硬编码 hex。

不要照搬的部分:
附件里的页面外壳、标题、说明文字、规格卡、试验台、来源说明一律不上站。
模块怎么呈现(卡片、标题、排布)沿用站点现有样式,不要跟着附件改版式。

本次差异:
- 当前{写错 / 缺了}{什么} → 应改成{什么}
- 当前{写错 / 缺了}{什么} → 应改成{什么}

明暗双版:跟随网页明暗主题切换显示(白肤显白版、黑肤同处切黑版),不在同一主题下并列铺两版。
```

## 二、无参考实现文件时(退而求其次)

```
【DS v{X.Y.Z}】{组件全限定名}
位置:{实际页面名}.html → 「{章节区块名}」,作为该页新增区块加入(非新开页面)

规范:
{从 skill 固化后文本抄来的定稿表述,不从校验图复制}

本次差异:
- 当前{写错 / 缺了}{什么} → 应改成{什么}
```

---

## 三、检查单(发之前逐条过)

- ☐ **开头注明版本号**
- ☐ **只含定稿表述**:没有「决议 / 待确认 / 源稿已废 / 讨论过程」等过程性表述
      (纠错指向除外,且只说"应为什么"不说"为什么改")
- ☐ **写差异 + 纠错指向**:每条都是「当前写错 / 缺了什么 → 应改成什么」,不只给目标值,不让整页重做
- ☐ **定位用站点实际页面名**(如行情→`scene-quote.html`),**不用逻辑名**(如「自选页」)虚指
- ☐ **不夹带站内下载 skill 包的升级要求**(那属发布 / 部署阶段统一更新,`process.md` §4.5)
- ☐ **不附「做完请导出」**(整站导出耗用户点数;改完回一句确认即可)
- ☐ **不写未确认的 carry-over**(「若上一批某项未完成则继续 / 补做」这类)
- ☐ 框内是纯提示词正文,**对用户的说明写在框外**

## 四、发出之后

**⛔ 发下一份前,必须先问用户上一份的执行 / 落地情况**(是否做完、是否需先对账),确认后再发新的。

**什么时候才明确索取一次导出**(仅这两种,同一份导出兼作两用、不重复索取):
1. 需对账取证(`process.md` §4.3)
2. 打包 / 部署前(`process.md` §4.5)
