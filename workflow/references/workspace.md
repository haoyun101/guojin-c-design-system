# 工作区结构 · 本地目录与权限

> **用途**:多窗口(主线-大脑 / 主线-手 / 各支线 / Design)并行时的**本地目录约定**。
> **设计原则**:**边界由目录权限保证,不靠模型自觉**(`process.md` §4.8「把合规从靠自觉改为靠机制」)。
> **边界**:本文件只定**本地工作区**结构;DS skill 包**内部**结构不受影响(仍按其 `SKILL.md` 三层架构 + `SKILL.md` §2 总则3.3 全 ASCII)。

---

## 一、总览

工作区根路径:`~/Desktop/协同项目/C端设计系统`

```
C端设计系统/
├── skill/                      ← 【正式库】执行真值(解压后的 DS skill 目录;设计真值在 Figma,见总则1)
│   └── guojin-securities-design_vX_Y_Z/
├── drafts/                     ← 【草案区】支线产出
│   ├── common/                 ← 支线-通用组件
│   ├── wealth/                 ← 支线-理财组件
│   └── {场景}/                 ← 按需新增,用 8 业务域英文名
├── site/                       ← 【站点区】
│   ├── source/                 ← Design 原始导出
│   └── deploy/                 ← ASCII 化后可上线的部署包
├── meta/                       ← 【元文档】本工作流 skill 包 + 《项目总览》+《站点版本戳维护表》
└── 历史文件/                    ← 【归档】旧版本交付件(`process.md` §4.5)
```

**命名**
`skill/` 与 `site/` 的内容会被打包上传,内部一律 ASCII(`SKILL.md` §2 总则3.3);工作区自身的顶层目录名用 ASCII 小写,`历史文件/` 沿用 `process.md` §4.5 原名不改。
**`meta/` 里活动件的版本号用点号**(如 `_v1.4.md`),ASCII 下划线命名不适用于 `meta/`——但本工作流 skill 包是要上传的包,其顶层目录名仍走 ASCII 下划线(如 `guojin-design-workflow_v6_2/`)。

**五目录之外**
工作区根另有 `skill实际应用测试/` —— 用户私有测试区,存放发给各大模型做读取 / 挂载测试的 skill 副本与测试产物。**不属协作目录体系**:主线-大脑、主线-手、各支线一律不读、不写、不归档、不清理,除非用户当次明确指定。归档整理(§六)时跳过该目录;保留几版由用户自行管理,不设协作侧策略。

**归档原则** → 见 §六(本处不重复,避免两处反向漂移)。

## 二、各目录职责与权限矩阵

| 目录 | 主线-大脑 | 主线-手 | 支线-组件 | Design |
|---|---|---|---|---|
| `skill/` | 判断 / 裁决(经手执行) | **读写(唯一写入方)** | **只读** | ❌ |
| `drafts/{支线}/` | 经手读 | 读 | **各自只写自己那个** | ❌ |
| `site/` | 判断 | 读写(打包 / 改名 / 注入) | ❌ | 产出源 |
| `meta/` | 读 + 提增量提案 | 读写(按大脑指令改) | 读 | ❌ |
| `历史文件/` | — | 读写(按指令归档) | ❌ | ❌ |

**唯一写入方原则**:`skill/` 只有【主线-手】能写,且写什么由【主线-大脑】决定。**版本号由大脑签发、手只执行写入**(不自行判断升哪位)。

**⚠️ 主线-大脑无本地访问能力**(Claude Chat),它对文件的一切读写都经【主线-手】执行,或由用户手动上传 / 下载。

**系统文件不计入预期内容**:macOS 的 `.DS_Store`、`__MACOSX/` 目录及其下一切、`._` 开头的 AppleDouble 伴随文件(及同类由系统自动生成、删了会自动重建的文件)**不属于任何目录的预期内容**——收尾核对时**不报为偏差、不清理、不必请示**。只有当用户明确要求清理时才动。

> 本条最初(v6.2)只写了 `.DS_Store`,**又是一次按旧事实集写死的枚举**——`__MACOSX/` 与 `._*` 是同一类东西,只是直到 v6.6 才在实战里撞上(`multi-window.md` §8 第二条)。
> 理由:它每次都会重新出现,报一次偏差就要裁决一次,纯属噪声。

## 三、支线怎么读 skill

**直接授权 `skill/` 只读**——已实测确认执行端授权可区分只读与可写,故无需副本。

- 支线只授权:`skill/`(只读)+ `drafts/{自己那个}/`(读写)
- 支线**够不到** `skill/` 的写权限,边界由授权保证,不靠自觉
- 无本地访问能力的支线(Claude Chat)照旧由用户上传冷启动包(`multi-window.md` §3.2)

> 曾设计 `drafts/_skill-ref/` 只读副本方案,因授权支持只读而**取消**;该目录应清理。

## 四、草案区结构(支线交回格式)

每个支线目录按**批次**分文件夹,一个组件 / 一批一个:

```
drafts/common/
└── C01-button_20260902/
    ├── 交付说明.md          ← 交付包 7 项(标识/凭证/真值/嵌套/多版/裁决点/未完成)
    ├── button.html          ← 参考实现候选(须 check-page.py 0 P0)
    └── 素材/                ← 图标 SVG、截图等
```

> 7 项的内容与填写骨架见 `multi-window.md` §5 与 `assets/templates/handoff-package.md`。

**主线-手的机械检查项**(不含裁决,只查齐不齐;完整执行纪律见 `execution-standard.md`):

- ☐ `交付说明.md` 存在且 7 项齐全
- ☐ 参考实现已跑 `check-page.py`,P0 = 0
- ☐ 无硬编码 hex(应为 `var(--)`)
- ☐ 数值标注含【变量绑定名 + hex】两者,读不到的标 ⚠️
- ☐ 文件名 ASCII

缺项 → 标 ⚠️ 报回主线-大脑,**不自行补全**(补全属裁决)。

## 五、执行卡与反馈(都不落盘)

**执行卡**:主线-大脑产出的执行卡由用户下载到 `~/Downloads`,执行端**直接从下载文件夹读取**,不搬进工作区。执行卡是一次性产物,**用完即弃,不归档、不留存**。

**执行反馈**:同样是一次性过程产物。**输出为 md 文件到 `~/Downloads`**(文件名带本轮任务编号 + 日期时分),回复只给路径;**绝不写进工作区**。写不进下载文件夹时降级为贴代码块。详见 `execution-standard.md` §五——该节形态为**安全底线**,不受单次执行卡指令覆盖。

> 故工作区**不设 `tasks/` 目录**。承 `SKILL.md` §2 总则1「事实源在文件不在对话」——事实源是 `skill/` 与 `meta/`,执行卡与反馈都不是事实源。

## 六、站点区与归档

- **`site/source/`**:Design 原始导出;**`site/deploy/`**:ASCII 化后可上线包;`SITE-CHANGELOG.md` 放 deploy 内,为站点版本唯一权威(`process.md` 总则3.5-5)。
- **`历史文件/`**:承 `process.md` §4.5 —— 各版本线**只在原位保留最新交付件**,旧版本移入此处。由【主线-手】在发布 / 打包收尾时执行,判定与处置规则见 `execution-standard.md` §八。
