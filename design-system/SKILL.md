## 定位 & 三层架构

**这个 skill 是什么**:一份喂给 AI 的设计规则说明书。生成证券/金融类移动端界面时,本 skill 让任意模型产出的页面在颜色、字体、间距、圆角、涨跌色上与国金证券设计系统统一。

**规范分三层**:**① 基础规范**(`references/foundations.md`,全局通用)→ **② 通用组件**(`references/components.md`,≥2 场景复用)→ **③ 业务场景**(`references/scenarios/`,单一场景专属,场景内复用)。

**取用顺序**:
- 使用者**声明了业务场景**(受控词:基础 / 账户 / 增值 / 行情 / 交易 / 理财 / 资讯 / 端外,例:"做账户开户的页面优化")→ **优先读对应场景文件**,场景已覆盖的项按场景(对全局的差异是合法覆盖);未覆盖的回退 ② 通用组件 → ① 基础规范。
- **未声明场景** → 只用 ① + ②,不得自行猜测场景、不得擅自取用场景层规范。
- 场景文件标 [待] 的项=尚未固化,按回退链取用。

## 🔴 硬规则(NEVER / ALWAYS · 红线,不可违背,最高优先级)

1. **颜色方向(证券核心)**
   - **价格涨跌**:涨 = `--CS1`(红)/ 跌 = `--CS2`(绿)/ 平 = `--CS3`(灰)。**NEVER 涨绿跌红。**
   - **交易动作**:买 = `--CN1`(红)/ 卖 = `--CN3`(蓝)。与「涨跌」分属两组、不可互换。
   - **操作结果**:成功 = `--CF7`(绿,结果页"操作成功"等操作反馈)/ 失败·警告 = `--CF1`(红)/ 链接 = `--CF3`(蓝)。绿在**价格语境**专表「跌」(`--CS2`)、在**操作结果语境**表「成功」(`--CF7`)——同色值不同语义;**同屏既有行情价又有成功提示时,靠位置/文案区分,避免误读。**
2. **ALWAYS 用 `design-tokens.css` 变量取色,NEVER 硬编码 hex。**
3. **ALWAYS 按用途选语义 token**(文本 CT、背景 CB、按钮 CN、涨跌 CS、图标 CI、线框 CL);**NEVER 直接选原子色**(语义层确无对应才退回)。
4. **ALWAYS 以 750 为唯一实现基准**:生成产物画布宽 750,所有尺寸/字号/间距/圆角直接用 750 标注值,**不做任何 ÷2 换算**;`--SP*`/`--RD*` token 即 750 值,直接取用。
5. **ALWAYS 字号从 S1–S8 取值,NEVER 用规范外字号。**
6. **ALWAYS 数字/金额用 `--font-num` 并开启 `tnum` 等宽;NEVER 用文案字体写价格,NEVER 混用两种字体。**
7. **ALWAYS 深色模式靠容器加 `data-theme="dark"`,语义色自动切换;NEVER 为深色另写一套色值。**
8. **NEVER 在状态栏/刘海/底部 Home Indicator 区放可点击元素;用 `env(safe-area-inset-*)` 自适应。**
9. **资产引用按粒度钉死,别一刀切**:① **固有/行为性资产**(组件自带、不随场景变,如表头排序三角)→ 定死库内确切文件+状态;② **可替换槽位**(通用组件里随场景换的位,如表头左侧标识图标)→ 只定**槽位规格**(数量/尺寸/位置/取自哪个库/颜色)+ 注明「具体由场景选、可替换」,**不定死文件**;③ **场景演示/业务实例**(如自选页)→ 定死该实例用的确切文件。**NEVER 用「…」/「见某文件夹」式开放表述蒙混**(那是没区分清,不是「可替换」)。判据:只读规则文字,能否唯一重建出**该层该有的精度**(固有层→具体文件;槽位层→槽位规格;实例层→具体文件)?不能就补到能。

## 操作顺序(五步 + 两道强制闸门)

> **可靠性三层(本 skill 的合规保障,不靠模型自觉)**:① 降摩擦——一切可复用资产(图标/组件/token)都登记在 `assets/library-index.json`,用前先查、照抄引用,比手画/重写更省事;② 强制产出 BOM(下方闸门 A)让"查库"变成必须交付的产物;③ 确定性校验 `scripts/check-page.py`(闸门 B)兜底拦截。三层缺一不可。

**五步速览(先看全貌,下面逐项展开)**:**0** 判任务模式(还原/新建)& 输出渠道 → **1** 判场景 + 读硬规则 → **2** 搭骨架(page-shell,间距交容器) → **3** 摆组件(过闸门 A 出 BOM、A2 命中库必复用) → **4** 取色取尺寸只用 token → **5** 跑自检(闸门 B `check-page.py`,P0=0 才交付)。

**先判两件事(决定后续怎么取信息、资产怎么引用):**

**① 任务模式(决定要不要用 Figma 工具)**
- **还原 · 有源**:用户给了 Figma 节点 / 截图 / 具体设计稿 → 按下方「取信息分工」用 `get_metadata` / `get_design_context` 核形态。
- **新建 · 无源**:只说"做个 X 页面"、无特定源 → **跳过 Figma 工具**,形态以 `references/component-quickcards.md` 辨识特征 + `view` 参考实现为准。
- 两种模式**都必过**闸门 A / A2 / B。

**② 输出渠道(决定资产怎么引用;拿不准 → 默认自包含最稳)**
- **独立 HTML · 整包交付**(HTML + 同级 `assets/` 一起下载/本地打开)→ **相对路径**引用,还原≈100%,工程化首选。
- **独立 HTML · 会单独预览/发链接**(聊天里点开、发链接)→ 同级 assets 不被伺服、相对路径资产全 **404** → **必须自包含**(SVG 内联 + 字体 base64,或粘 `sandbox-header.html`)。
- **show_widget 内联沙盒**(读不到磁盘)→ 资产必内嵌:**最终产出时**把 `assets/components/sandbox-header.html` 整段粘进 `<body>` 开头,iconfont / GJType / 底导 sprite(`<use href="#gj-bn-...">`)/ 小宝 / tokens 即全就绪。**平时不要读或贴完整 `sandbox-header.html`**;想低成本看它提供哪些 id/类名/`<use>` 用法 → 读骨架版 `sandbox-header-skeleton.html`(约 16KB);**非高保真才用**(长 base64 有截断风险)。
- **单资产 >150KB**(如 `agent-orb-wave` 约 197KB PNG)在单文件场景**勿 base64 内联**(易截断、复杂 filter/gradient 移植降级)→ 外链或占位。
- **self_contained 速查**:组件能否直接用于单文件 / widget,以 `assets/library-index.json` 中每个组件的 `self_contained` / `requires` / `note` 字段为准;拿不准时默认整包相对路径或粘贴 `assets/components/sandbox-header.html`。

**⛔ 闸门 A · 出料单 BOM(第一步、动手前强制,跳过 = 本次输出作废)**:先查 `assets/library-index.json`,把本页要用的**每个图标、每个组件、每个关键色/字**列成《用料清单》表,逐项写明**库内确切引用**(iconfont `icon-xxx` / SVG 路径 / 组件参考实现路径 / token `var(--xx)`);库内确实查不到的标「[待]待补」。**BOM 填不出来 = 没查库,必须先查再动手。** 反复嵌套复用的组件(如行情卡片在指数组合里、个股标签在列表项里)一律在 BOM 里指到参考实现,不得就地重写。

**⛔ 闸门 A2 · 命中库 = 必复用 + 先核形态(与 BOM 同级,动手前强制)**
- **命中即复用,不许"参考着自写"**:BOM 里凡标了库内引用(有参考实现 `assets/components/*.html` 或 `components.md#章`)的条目,必须复用库内引用;手写一套近似类名 = 本次输出作废、返工。**读取顺序按成本走**:先查 `library-index.json` / `component-quickcards.md` / 对应 `*.usage.md`;轻量说明足够时,大型参考实现只作为可引用真源,**不默认全文读取**。只有要修改该文件、排查内部 bug、或轻量说明无法回答结构问题时,才读参考实现全文。判据:产出里每个命中库的组件,都能追溯到"实际引用了哪个参考实现文件 / 库类名 / usage 指针"。
- **先核形态,后选变体**:命中库组件动手前先确认形态/变体——**【还原·有源】先 `get_design_context` 看截图**确认;**【新建·无源】无截图可看 → 直接按 `references/component-quickcards.md` 辨识特征 + `view` 参考实现确认**。尤其**一名多态**的:底部导航(智能体球版 vs 通用 N 等分白条)、tab(下划线/胶囊/连体)、列表表头(左标识三变体)、标题栏(一/二/三级)。**两种模式都严禁凭 metadata 的矩形尺寸脑补形态**(如见 `Rectangle 750×166` 就当成白底底导——本系统实测最大返工源)。
- **选变体先查速查卡**:`references/component-quickcards.md`(约 2KB:每组件形态变体+辨识特征+关键值+复用方式),命中后再读 `components.md` 对应章 / `view` demo,**不必为"长什么样"先吞 62KB components.md 或 251KB demo**。

**取信息按成本分工(还原·有源任务用;新建·无源任务无 Figma 工具,跳过本段)**
- **结构** → `get_metadata`(便宜):节点/文本/坐标/尺寸/层级。
- **形态·变体** → `get_design_context` 截图(关键节点才用):胶囊 vs 白底、图标真实形状、装饰底纹。
- **样式数值** → 参考实现 / `component-quickcards.md` / `design-tokens.css`(免费):类名、token、真值。
- 红线:**metadata 给的是结构信息、不是视觉信息;用结构脑补视觉必翻车。**

**「1:1 还原」与「用标准组件」冲突时**:以**设计稿截图为视觉真相**,组件参考实现为实现手段。截图与标准组件形态冲突时——先判是不是该组件的**已登记变体**(查速查卡辨识特征);确属运营定制 → 在最接近的标准组件基础上改、**并标注差异**,不弃用标准件另起一套。

1. **判场景 + 读硬规则**:先看使用者是否声明业务场景(规则见上「定位 & 三层架构」);硬规则优先级最高,不可违背。
2. **搭页面骨架(用 page-shell,模块间距交容器、别自搭)**:画布宽 750;按「安全区」表留出状态栏/导航/底部 Tab/Home Indicator;选导航(`components.md` 三:导航栏-顶部-{场景} / 导航栏-底部)。**布局套 `assets/page-shells/` 骨架**:按页面层级选 `data-level`——**一级页面(首页/自选/交易/理财/我的)→ `data-level=1`(边距&模块间距 SP4(16px));二级页面 → `data-level=2`(SP6，24px)**;**每个模块包成 `<section class="gj-module">` 塞进 `<main>`,模块间距由容器 `gap` 单点保证,严禁每模块各自加 `margin-top` 或用 `height` 撑间距**(跨模块间距漂移正源于此)。范例:运营长页 `home-ops-shell.html`、二级吸顶 tab 页 `detail-tab-shell.html`(吸顶 tab 复用 C04 `tab-下划线-二级`)、列表页 `list-shell.html`。
3. **摆组件**:**先按场景文件的『自上而下装配顺序』定区块竖向次序**(行情/自选页见 `scenarios/market.md §2`;场景未给则按 导航→内容区〔卡片/tab/表头/列表〕→底部导航 常规次序),再逐块取 `components.md` 的组件,**用全限定名定位**(按钮-{风格}-{档} / 文字按钮-{24|26|28} / 标题栏-{一级|二级|三级} / tab-{下划线|胶囊|连体}-{档位}(-{左固|等分|通栏}));数值直接抄该组件参数表(750 值),示意文案用通用占位。组件**优先引用参考实现**(BOM 里已指明),不就地重写。**图标按 BOM 用库内引用**:① 单色图标先查 IconFont(`assets/icons/fonts/iconfont.css` / `icon-palette.html`,如 `icon-zixuanzijin` 资金 / `icon-zixuanzixun` 资讯 / `icon-bianji` 编辑 / `icon-shixinjiantou-you` 右箭头);② 渐变/特效查 SVG 目录(`common/` / `{场景}/` / `bottom-nav/` / `gradient/`);③ 库内**确实没有的,可手画占位**并标「[待]待替换」。关键:**库里有就必须用库里的,不在库已有时自创画法**(工作流 4.1 准入第7条)。
4. **取色取尺寸只用 token**:间距使用SP0–SP10，圆角使用RD0–RD10（见 foundations §4–§5）。精确命中档位的参数引用对应token，例如 `var(--SP7)`、`var(--RD4)`；既有非标准参数保留原值与写法，不就近归档。复合参数逐项处理，例如 `padding: 16px 6px` → `padding: var(--SP4) 6px`。把 `assets/design-tokens.css` 的 `:root` 块放进输出样式顶部；颜色按语义引用，例如 `var(--CT1)`。**特殊情况**:`0` 直接写 0(写 `var(--SP0)` 也合法);定位偏移 `top/right/bottom/left/inset` 写像素;**胶囊 / 全圆角用 `var(--RD9)`**(组件章另有规定的按组件章,如 C01 按钮圆角 = 高 ÷2、胶囊 tab 36/50);圆形百分比、SVG 图形写原值。
5. **跑自检**:逐条过文末「自检清单」+ 所用组件章的专项自检,有不符就改到全过。

**闸门 B · 交付前校验(强制,不可跳过)**:对生成的页面跑 `python3 scripts/check-page.py 页面.html`;**P0 必须为 0 才能交付**(P0=手画图标等硬违规),P1 逐条复核确认。这是不依赖记性的最后兜底——模型会忘,脚本不会。出图前回扫 + 此校验双保险。

## 命名与示意文案(总则)

- **组件全限定命名**:引用任何组件用「**族-形态-档位(-排布)**」;**档位主键 = Figma 变体属性值**(M/S/XS、60/80/100、一级/二级/三级),禁止用推导值(高度/宽度)当主键;**禁止裸档位**(✗「80档」「XS」 ✓「tab-连体-80」「tab-胶囊-XS」)。同一变体值有分叉时以括号区分(tab-胶囊-S(字24) / S(字28))。排布受控词仅:**左固 / 等分 / 通栏**。曾用名只存于各组件章节对照表,新表述一律用全限定名。各族全限定名清单见 `references/components.md` 文件头「命名引用」。**业务组件(场景层)命名带场景前缀「{场景}/族-形态-档位」**(例:基础/智能体/导航栏-对话);场景名用受控词:基础/账户/增值/行情/交易/理财/资讯/端外(基础、端外含子域,用二级前缀如 基础/首页/…、端外/微信小程序/…)。
- **示意文案 = 通用占位**(所有组件与演示产物适用):标题「标题名称」、副标题「副标题」、tab「标签1 / 标签2…」、按钮「按钮文案」;**禁止真实业务词与随意词**。
